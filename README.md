## 🚀 Run Locally

### Prerequisites

- **Docker & Docker Compose** (recommended for full stack)
- **Java 17** and **Maven** (local backend development)
- **Node.js 20+** and **npm** (frontend and test suites)
- **Allure CLI** (optional, for unified reports): `npm i -g allure-commandline` or [Allure releases](https://github.com/allure-framework/allure2/releases)

### Option 1 — Docker full stack (recommended for evaluators)

```bash
cd b2b-ecommerce-platform
cp .env.example .env   # set DB_PASSWORD
make up
make down              # stop when done
make logs              # follow container logs
```

| Service | URL |
|---------|-----|
| Frontend | http://localhost:3000 |
| Backend API | http://localhost:8080 |
| Health check | http://localhost:8080/api/health |

### Option 2 — Local development (Postgres in Docker, apps on host)

```bash
cd b2b-ecommerce-platform
make install
make dev
```

| Service | URL |
|---------|-----|
| Frontend dev server | http://localhost:5173 (proxies `/api` to backend) |
| Backend API | http://localhost:8080 |

Ensure `DB_PASSWORD` is set in `.env` or your shell when running the backend outside Docker.

### Option 3 — Run tests only

Backend must be running on port **8080** (via `make up` or `make dev`):

```bash
make test              # API → Postman → E2E
make test-allure       # all suites with Allure output
make allure-report     # generate unified HTML report
make allure-open       # open report in browser
```

| Command | Description |
|---------|-------------|
| `make install` | Install Maven and npm dependencies |
| `make dev` | Start Postgres + backend + frontend locally |
| `make up` | Build and start full Docker stack |
| `make down` | Stop Docker stack |
| `make test` | Run API, Postman, and E2E tests |
| `make test-allure` | Run all suites with Allure reporters |
| `make allure-report` | Generate unified Allure HTML report |

## 🔌 API Overview

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/health` | Application health (`status: UP`) |
| `GET` | `/api/products` | List all products |
| `GET` | `/api/products/{id}` | Get product by ID |
| `POST` | `/api/products` | Create a product |
| `PUT` | `/api/products/{id}` | Update a product |
| `DELETE` | `/api/products/{id}` | Delete a product |

Example product payload:

```json
{
  "name": "Industrial Widget",
  "price": 49.99,
  "description": "Heavy-duty widget for B2B orders",
  "stock": 500
}
```

Spring Actuator endpoints (`/actuator/health`, `/actuator/info`) are also exposed for observability.
